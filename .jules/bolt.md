## 2025-05-22 - Granular File Caching for Case Database
**Learning:** `iter_saved_case_records` was performing synchronous file reads (`json.loads(path.read_text())`) inside a loop on every access. As the database grows, this O(N) I/O becomes a major bottleneck for features like AI Learning and Search.
**Action:** Extracted the file reading logic into `_load_single_case_record_cached` decorated with `@st.cache_data`. This helper accepts the file path and its `st_mtime` as arguments. This pattern ensures that we only pay the I/O cost when a specific file has actually changed, making repeated iterations over the database effectively O(K) (where K is the number of modified files) instead of O(N).
